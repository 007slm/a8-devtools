# A8 Agent Mind 通用架构与文档治理总则 (Universal Mind Rules)

> 由全局插件 `a8-agent-mind` 统一分发，适用于宿主机全部仓库。单仓独有业务红线维护于各自 `.agents/rules/`。

---

## 一、 人机协作与交互铁律

- **纯中文直白交互**：始终用简体中文短句陈述客观事实与物理路径，禁用“赋能/抓手/全方位/旨在/不仅…而且…”等 AI 空话套话或先写总结式废话套头。
- **路线对齐与问题透明**：已定案的架构路线不轻率推翻；遇阻碍直接抛出共同决策，严禁擅自偏离。
- **品味沉淀守时克制**：方案评估（如 `/plan`）、讨论未定案或代码未落地验证前严禁提前提议规则沉淀；未由用户显式调用 `/a8-improve` 时，严禁自行预判生成或嵌入复盘提案卡片；具体模块的排障根因与修法归入 `docs/`，严禁当成红线规则堆砌。
- **动工前挑战复杂路线（官方与极简优先）**：做非简单改动前，先查是否有官方标准方案或更简单稳健的做法（严禁放着官方原语不用而自造复杂方案）。若有更优解，动工前先直说一次：“*确定要用 X 吗？Y 更简单稳健，因为 Z。*”再按用户选择执行。**先挑战整体前提与技术路线，别只抠局部细节；保持沉默即代表你已核对过官方方案与替代路径，确认当前就是最优解。**
  <!-- 2026-11-18: "[39ddbe19] 容易把简单事情做复杂或放着官方方案不用；做非简单改动前若有更简稳健做法先提一次挑战整体路线，沉默代表已核对确认最优" -->
- **可逆先干与汇报纪律**：技术路线已对齐、非 $F\times S < 10$ 边界、非 `/a8-improve` 规则写盘且非不可逆写操作（删生产数据、强推或外发消息）时，可逆局部改动直接完成并附 `[实测]` / `[推断]` / `[待确认]` 与证据汇报，禁反复问“要我做吗”。
- **工作流按需路由**：多阶段研发、深度排障、性能优化或长程任务按需加载 `a8-workflow` 对应场景指南（日常一两行小改免开）。
- **主人翁责任感**：对代码库长期可维护性与架构整洁度负责。

## 二、 顶层架构设计哲学

- **全生命周期闭环与边界自洽**：在模块职责边界内完成物理事实确权与状态自洽，不向下游泄露不确定性；下游遇异常必须顺因果链回溯至源头根治，严禁打补丁或假自愈掩盖。
- **显式状态机驱动与强类型建模**：多阶段生命周期、异步同步与复杂流转必须用有界状态枚举与显式跃迁守卫驱动（必要时附 Epoch/失败原因），让非法状态在编译期无法构造（优先用枚举、联合类型与独立区分 ID 类型并从权威 Schema 派生类型，用注册表或映射表取代跨文件散落的重复 `if/else` 与同步布尔标记；局部直白无扩张趋势则保持朴素）。
- **不变量先行与幂等收敛（Invariants First）**：没有不变量的状态模型只是严谨地表达“什么都没有”。写业务逻辑前先定核心数据结构与并发所有权；涉及状态流转、并发槽位/许可借还、缓存失效或跨组件集合同步时，先明确核心不变量（守恒式、单调 Epoch 守卫、移出即失效、Fail-Closed 门禁）；状态变更与恢复基于当前物理状态向目标状态差量幂等收敛，锁与临时产物自带崩溃可识别陈旧凭证并经临时路径原子重命名落盘；强状态模块优先配合随机操作序列单测每步校验不变量。
- **直白命名、平实表达与受控术语闭环（基本可读性铁律）**：AI 设计的代码标识符（尤其是**状态枚举、类名、接口字段、函数与变量**）必须使用**大陆程序员常用的简单高频英文单词**（物理判据锚点：状态命名优先用 `INIT` / `SNAPSHOT` / `SYNCING` / `READY` / `DIRTY` / `ERROR` / `STOPPED` 等基础词，**严禁**使用 `STALE`、`QUIESCING`、`EPHEMERAL` 等生僻词、炫技长词或自造晦涩缩写）；设计文档（`AGENTS.md`、常青文档 `docs/evergreen/`、工作记录 `docs/records/`）、架构图与注释必须用**平实直白的大白话**直接说清“什么情况下发生什么、怎么处理”——**除业界通用标准技术词与反引号包裹的真实代码标识符外，可直接使用项目术语表 `docs/glossary.md` 中的术语；凡不在术语表中的概念，必须二选一：① 补充登记进 `docs/glossary.md`（一句话普通话讲清），或 ② 直接用普通话解释**，**严禁**直接抛出未登记的自造简称、架构隐喻或压缩黑话（反例：未定义即写“双通道、三平面、流式折叠、时序拍扁、黑板上下文、毒丸、灌流相位”）。
  - **原因 (Why)**：代码易读、文档让人一眼看懂是最基本的核心原则；AI 压缩文档时随手造黑话会让读者（甚至作者本人）看不懂，建立术语表并强制“要么入表、要么说普通话”才能避免文档越来越晦涩难维护。

  <!-- 2026-11-18: "[39ddbe19] 状态用大陆程序员常用的单词 STALE 这种的不要；代码易读、设计文档容易让人理解是基本原则，否则文档晦涩、代码完全不能懂、越来越难维护" -->
  <!-- 2026-11-21: "写文档经常搞一些名字我都看不懂；建立术语表放 docs/glossary.md 并在 AGENTS.md 引用，常青文档和工作记录都可以用术语表里的词，不在术语表中的要么加术语要么用普通话解释" -->
- **先减后加、重设计于打补丁与降读者负担**：接入新需求先问“从零重搭会怎样”，重设计胜于打补丁；演进重构先删死代码、多余校验器与单调用方转发包装再建新形，按“返回值 > 局部变量 > 对象字段 > 模块态 > 全局态”收缩状态作用域，让新人 30 秒内答出“从哪来、谁能改”。
- **注释即代码异味（自表达与严格白名单）**：代码靠直白命名与清晰控制流自表达，严禁保留赘述、过时或用 `TODO`/`FIXME`/`临时`/`兜底`/`兼容`/`单元测试桩`/`忽略` 打掩护的注释（改码须同步清失效旧注释）。**白名单仅限**：① 许可证头；② 外部不可改依赖/平台/协议硬约束；③ 非缺陷性格式或风格 Lint 豁免；④ 公开 API 文档注释；⑤ `docs/records/` 或 Issue 链接及解释 Why/不变量的短注释。本仓自己代码的意外不留长注释辩护，直接改名、定型或重构消除；**压制抓真 Bug 或护安全规则的 Lint 抑制必须删除并根治**；其余诉求转化为更直白命名、自动化测试或 `docs/`。
  - **原因 (Why)**：不要让代理程序破坏代码库——未受约束的注释会快速腐化为噪音赘述、过时误导，以及合理化 hacky 实现并持续传播的“借口”。
  <!-- Judge-Category: implementation_hygiene | Triggers: //, /*, TODO, FIXME, HACK, 兼容, 兜底 -->
  <!-- 2026-11-21: "不要让你的代理程序破坏你的代码库；注释是一种代码异味，应转化为更好地命名的变量/函数（慎重拆碎小函数）、测试、根治或 docs/deferred/、常青文档/ADR" -->
- **拒绝伪健壮性**：严禁为了“理论上更稳”加入无原则兜底、冗余锁或猜测性保护代码。
- **旧模型干净退役**：兼容保留的旧入口必须第一时间剥离对全局共享状态的破坏特权；随功能废弃的触发源（`Runner`、`@PostConstruct`、`@Scheduled` 等）须连根删除。

## 三、 4 大正交维度黄金红线

> 下列维度的细粒度代码裁决规范沉淀于 `a8-agent-mind/decisions/*.decision.json`，此处保留总纲。

1. **演化与零擅自向后兼容**：未经用户明确批准严禁保留兼容层、双轨逻辑或死代码；重构迁移执行全生命周期逆向清缴，“拆旧再建新”，同波次更新测试断言新契约并删旧实现细节测试。
2. **边界纯净与单向分层**：模块间严格单向依赖；底层公共库、纯内核或轻量化边界组件严禁反向引入上层重型框架、业务容器或应用宿主依赖。**边界双自检**：仅在数据跨系统边界时解析校验一次（非跨界内部直接信任定型类型）；无框架依赖核心业务抽成纯函数让外壳薄调用。
3. **热路径高性能与事件驱动**：
   - **共享状态先物理隔离再谈锁**：并发读写同一文件、分支或配置对象时先物理拆分工作区/分片消除共享，仅单写者属真实不变量时才用细粒度锁或原子交换；高并发数据面热路径严禁方法级大粒度排他锁，持锁临界区、热路径及心跳内严禁阻塞等待或同步外查慢 I/O；
   - 异步协作与状态流转由显式完成信号或事件流驱动，严禁以 `sleep`、忙等或猜测性空转轮询替代确定性通知；确需的周期巡检或防抖须显式有界、闲置静默且不得掩盖上游状态失真。
4. **核心单一路径与错误第一现场保留**（命名与注释规范同见第二节）：
   - 同一核心领域能力全工程只允许存在唯一实现路径，严禁双轨转换；
   - **不加无用 `try/catch`**：当前层处理不了的异常直接向上透传；
   - **禁止 `catch` 后只打日志就吃掉异常，禁放宽窄兜底**：无明确有界重试、降级或清理重抛策略时，严禁在 `catch` 块仅记日志或返回空值/假成功；**勿把针对特定前置条件的窄兜底（如缺二进制 `ENOENT`）放宽为吞掉所有非零失败的静默 fallback**；确需收口须保留原始 `cause` 重抛或置入可人工接管失败态，统一用标准日志设施。
5. **语义红线审查 (`a8-judge`) 与提交前强制闸门 (`/a8-commit`)**：
   - **提交前强制收口**：回合级 `Stop` Hook 已卸载（日常多轮开发零打扰）；默认 `/a8-commit` 提交前**强制走完**「`judge_router.py` 路由 → `decisions_client.py` (Decisions API) 初筛 → 告警或高危架构面拉起 `arch-judge` 语义终审 → 重大变更文档核验」（`VIOLATED` 必先修复，`REQUIRES_APPROVAL` 须用户拍板）；仅用户显式传 `fast` / `--fast` 时跳过第 3 步语义审查（敏文件拦截与确定性门禁仍强检，**严禁 AI 擅自启用 `fast`**）；
   - **开发中按需提前体检**：大跨度重构（跨模块边界、核心契约、并发锁/状态机或兼容层清理）可在编码中途主动跑 `/a8-judge` 提前避坑；常规局部改动与同任务微调平时免重复拉起 `arch-judge`，交由 `/a8-commit` 统一兜底。

## 四、 编码实施与工程卫生红线

- **缺陷分级与 YAGNI**：改码前评估频率 $F(1\sim10) \times$ 严重度 $S(1\sim10)$。**$F \times S < 10$ 仅记为已知边界，严禁改码**；不为无人问及的罕见边缘或假想未来做超前设计；疑似罕见边界先向用户说明风险与代价，点头后再加。
- **真实表面实证与高 Token 禁自动红线**：严禁拿编译通过、假 Mock 绿灯冒充验证，单测只断言外部行为不死绑私有实现；**但为严控 Token 与耗时，日常改码优先用最轻量的编译、局部单测与 `scripts/lints/` 验绿**——仅当改动直接触及真实外部契约/驱动/端口/构建产物或用户明确要求时，才按 `<repo>/docs/verify.md` 跑对应最小实机表面。**以下 3 类高耗 Token 动作严禁 AI 擅自自动执行（仅用户显式点名时才启用）**：① 浏览器 UI 自动化（`/a8-ui-verify`）；② 多方案交叉实现对比 / 独立对抗找茬子代理；③ 重型端到端反复跑测或多轮 A/B 压测循环。
  <!-- 2026-11-22: "重型自动化验证、交叉对比、UI 自动化特别消耗 token 不应自动做；多代理/worktree 隔离完全交由 Antigravity 原生 swarm 标准逻辑，规则不介入" -->
- **连续失败熔断与脚本杠杆**：**连续 2 次基于同一前提修同一门禁失败必须停下，写出前提并先做实验直接证伪，严禁写第 3 次盲补**（证伪的试探性保护代码立即回退删净）；非平凡批量改写或核验优先写可复跑脚本自证。
- **拒绝过早抽象 & 入口定型**：只用一次的逻辑原地直接写，不提前抽象；外部输入仅在跨边界入口校验定型一次（见第三节第 2 条）。
- **脚本统一用 Node.js**：新建脚本核心逻辑一律用 Node.js（`.mjs`/`.js`）放 `scripts/` 目录，不再用 `.ps1` 写业务逻辑；确需快捷入口时，`.cmd`/`.ps1` 仅作参数透传调用 Node.js。
- **终端编码 & 环境卫生**：Windows PowerShell 命令前统一前置 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8;`；测试日志统一放 `logs/`，临时测试文件验完即删；信息不足先查代码文档再提问，禁止猜测。
- **后台进程探测**：Windows 常驻服务须脱离前台启动（如 WMI `Win32_Process.Create`），启动后必查「PID 存活 + 端口/句柄就绪 + 延迟 2s 防闪退复检」，探测失败抓第一现场日志，严禁掩盖失败。

## 五、 双层文档体系与仓库地图治理（防 `AGENTS.md` 超 24KB 截断）

- **先读地图、渐进式加载**：动工前先读**被改目标仓**根目录 `AGENTS.md`（跨仓查 `a8-agent-mind/repos.md`），编译测试先查 `docs/verify.md`，按需读命中的 **`docs/evergreen/` 常青文档**，仅深挖背景或排障时顺回链打开 `docs/records/`，禁全量铺开历史流水账。
- **文档分域、单篇职责纯洁与尺度边界**：各类文档各司其职不混写（禁把流水账写入常青或把设计说教混入验证地图）：
  - **共享术语表 (`docs/glossary.md`)** & **验证地图 (`docs/verify.md`)** — **`docs/` 根目录唯二合法单文件（均须 `<= 20,000 B`）**：`glossary.md` 用一句话普通话讲清项目专有词物理含义并附代码锚点，常青与工作记录共用（不在表中的非通用概念，要么补入表内，要么正文用普通话写清）；`verify.md` 只写改动模块验证路由、真实表面执行卡、本地环境盲区与基准防伪规范；
  - **常青文档 (`docs/evergreen/<domain>.md`)** — **高频主读、短小精悍**：只收跨模块/跨进程边界、非显而易见的状态机与不变量、共享 Schema/协议契约、生死阈值链路及 Fail-Closed/反直觉有意权衡与重新评估条件；最硬红线前置，图+表+短断言替代长文，减法原地覆盖；禁复述源码、禁流水账、禁源码穷举与未落地设想；参考体量常规域 `2~6 KB`、核心引擎域 `6~12 KB`（严禁 `> 20,000 B`），无需元信息头，关键坑点内联挂回链指向 `../records/`；
  - **工作记录 (`docs/records/YYYYMMDD-<TYPE>-<MODULE>-<SUBJECT>.md`)** — **轻量复检与溯源**：仅在触及「架构权衡、系统边界/契约变更、深层根因排查」时按 [`templates/work-record.md`](../templates/work-record.md) 写入（4 项头 + 4 段精悍要点，禁流水账，写清制约证据、被否方案、重评触发条件及**已测与未覆盖边界**）；**常规局部改动与简单 Bug 走单测与自表达代码（仅非显而易见边界留简明 Why 注释），严禁滥建工作记录**；
  - **暂缓与废弃隔离**：未落地设想放 `docs/deferred/*.md`；后续设计推翻或更新既有记录时，只改旧记录 `- **状态**：` 与顶部横幅，不篡改历史正文。
- **快慢双轨文档整合（日常顺手轻更新 + 每晚 20:00 全量梳理）**：
  - **日间快轨**：写完工作记录或完成触及系统真相/验证入口的改动后，直接在当前会话按既有上下文顺手轻量化更新对应的 `docs/evergreen/`、`docs/verify.md` 与 `AGENTS.md`（不要求当场面面俱到，**严禁**为此单独调用 `docs-sync` 子代理额外耗费上下文与 Token）；
  - **夜间慢轨**：由每晚 20:00 定时任务通过 `scripts/scan_docs_sync.mjs` 增量预检并全量梳理（或必要时手工显式调用 `docs-sync` 子代理），以**真实源码为最高事实源**（源码 > 工作记录 > 旧文档）深度校准补全 `docs/evergreen/`、`docs/verify.md` 与 `AGENTS.md`（仅写盘不提交，只读保留 `进行中` 记录）。
- **根目录地图与容量红线**：根目录 **`AGENTS.md`** 直接挂接 **`docs/evergreen/` 与 `docs/verify.md` 索引**（严控 **`< 20,000 bytes`** 防 Antigravity `24 KB` 截断），不建冗余 `docs/INDEX.md`；工作记录按需由常青回链打开或直接扫 `docs/records/`。
