# A8 Agent Mind 通用架构与文档治理总则 (Universal Mind Rules)

> 由全局插件 `a8-agent-mind` 统一分发，适用于宿主机全部仓库。单仓独有业务红线维护于各自 `.agents/rules/`。

---

## 一、 人机协作与交互铁律

- **纯中文交互**：始终使用简体中文回复。
- **路线对齐与问题透明**：已定案的架构路线不轻率推翻；遇阻碍直接抛出共同决策，严禁擅自偏离。
- **品味沉淀守时克制**：方案评估（如 `/plan`）、讨论未定案或代码未落地验证前严禁提前提议规则沉淀；未收到 Stop Hook `ASK_USER_UI` 唤醒且用户未调用 `/a8-improve` 时，严禁自行预判生成 `reflect_card.html`；具体模块的排障根因与修法归入 `docs/`，严禁当成红线规则堆砌。
- **动工前挑战复杂路线（官方与极简优先）**：做非简单改动前，先查是否有官方标准方案或更简单稳健的做法（严禁放着官方原语不用而自造复杂方案）。若有更优解，动工前先直说一次：“*确定要用 X 吗？Y 更简单稳健，因为 Z。*”再按用户选择执行。**先挑战整体前提与技术路线，别只抠局部细节；保持沉默即代表你已核对过官方方案与替代路径，确认当前就是最优解。**

- **主人翁责任感**：对代码库长期可维护性与架构整洁度负责。

## 二、 顶层架构设计哲学

- **全生命周期闭环与边界自洽**：在模块职责边界内完成物理事实确权与状态自洽，不向下游泄露不确定性；下游遇异常必须顺因果链回溯至源头根治，严禁打补丁或假自愈掩盖。
- **显式状态机驱动**：多阶段生命周期、异步同步与复杂流转必须用有界状态枚举与显式跃迁守卫驱动（必要时附 Epoch/失败原因），严禁靠多个散落布尔标记在下游反推状态。
- **不变量先行（Invariants First）**：没有不变量的状态模型只是严谨地表达“什么都没有”。涉及多阶段状态流转、并发槽位/许可借还、缓存失效或跨组件集合同步时，设计与改码前须先明确核心不变量（守恒式、单调时间戳/Epoch 守卫、移出即失效、Fail-Closed 门禁），严禁只画状态流转图而忽略全局恒真条件；强状态模块优先配合随机操作序列单测在每步转移后校验不变量。
- **直白命名、平实表达与受控术语闭环（基本可读性铁律）**：AI 设计的代码标识符（尤其是**状态枚举、类名、接口字段、函数与变量**）必须使用**大陆程序员常用的简单高频英文单词**（物理判据锚点：状态命名优先用 `INIT` / `SNAPSHOT` / `SYNCING` / `READY` / `DIRTY` / `ERROR` / `STOPPED` 等基础词，**严禁**使用 `STALE`、`QUIESCING`、`EPHEMERAL` 等生僻词、炫技长词或自造晦涩缩写）；设计文档（`AGENTS.md`、常青文档 `docs/evergreen/`、工作记录 `docs/records/`）、架构图与注释必须用**平实直白的大白话**直接说清“什么情况下发生什么、怎么处理”——**除业界通用标准技术词与反引号包裹的真实代码标识符外，可直接使用项目术语表 `docs/glossary.md` 中的术语；凡不在术语表中的概念，必须二选一：① 补充登记进 `docs/glossary.md`（一句话普通话讲清），或 ② 直接用普通话解释**，**严禁**直接抛出未登记的自造简称、架构隐喻或压缩黑话（反例：未定义即写“双通道、三平面、流式折叠、时序拍扁、黑板上下文、毒丸、灌流相位”）。
  - **原因 (Why)**：代码易读、文档让人一眼看懂是最基本的核心原则；AI 压缩文档时随手造黑话会让读者（甚至作者本人）看不懂，建立术语表并强制“要么入表、要么说普通话”才能避免文档越来越晦涩难维护。

  <!-- 2026-11-21: "写文档经常搞一些名字我都看不懂；建立术语表放 docs/glossary.md 并在 AGENTS.md 引用，常青文档和工作记录都可以用术语表里的词，不在术语表中的要么加术语要么用普通话解释" -->
- **注释即代码异味（自表达替代）**：代码必须靠直白命名与清晰控制流自表达，严禁保留赘述、过时或掩盖缺陷的注释（物理判据锚点：禁止给自解释变量/方法/语句写同名翻译或逐行复述；禁止用 `TODO`/`FIXME`/`临时`/`兜底`/`兼容`/`单元测试桩`/`忽略` 为 hacky 实现打掩护；改码时必须同步清理因变更而失效的旧注释；仅允许用平实大白话保留解释 **Why、非显而易见边界或不变量** 的决策注释，其余诉求分别转化为：**① 更直白的变量/函数命名（不为此强行拆出一堆碎小函数）、② 自动化测试、③ 直接顺因果链根治（确需延后则记入 `docs/deferred/` 或缺陷单）、④ `docs/evergreen/` 常青文档或 `docs/records/` ADR**）。
  - **原因 (Why)**：不要让代理程序破坏代码库——未受约束的注释会快速腐化为噪音赘述、过时误导，以及合理化 hacky 实现并持续传播的“借口”。

- **拒绝伪健壮性**：严禁为了“理论上更稳”加入无原则兜底、冗余锁或猜测性保护代码。
- **旧模型干净退役**：兼容保留的旧入口必须第一时间剥离对全局共享状态的破坏特权；随功能废弃的触发源（`Runner`、`@PostConstruct`、`@Scheduled` 等）须连根删除。

## 三、 4 大正交维度黄金红线

> 下列维度的细粒度代码裁决规范沉淀于 `a8-agent-mind/decisions/*.decision.json`，此处保留总纲。

1. **演化与零擅自向后兼容**：未经用户明确批准严禁保留兼容层、双轨逻辑或死代码；重构迁移执行全生命周期逆向清缴，“拆旧再建新”。
2. **边界纯净与单向分层**：模块间严格单向依赖；底层公共库、纯内核或轻量化边界组件严禁反向引入上层重型框架、业务容器或应用宿主依赖。
3. **热路径高性能与事件驱动**：
   - 高并发数据面热路径严禁方法级大粒度排他锁，改用细粒度锁或无锁结构；持锁临界区、热路径及心跳内严禁阻塞等待或同步外查慢 I/O；
   - 异步协作与状态流转由显式完成信号或事件流驱动，严禁以 `sleep`、忙等或猜测性空转轮询替代确定性通知；确需的周期巡检或防抖须显式有界、闲置静默且不得掩盖上游状态失真。
4. **核心单一路径与错误第一现场保留**（命名与注释规范同见第二节）：
   - 同一核心领域能力全工程只允许存在唯一实现路径，严禁双轨转换；
   - **不加无用 `try/catch`**：当前层处理不了的异常直接向上透传；
   - **禁止 `catch` 后只打日志就吃掉异常**：无明确有界重试、降级或清理重抛策略时，严禁在 `catch` 块仅记日志或返回空值/假成功；确需收口须保留原始 `cause` 重抛或置入可人工接管失败态，统一用标准日志设施。
5. **AI 自主终审 (`a8-judge`) — 仅限高架构风险、严禁高频增量触发**：
   - **高门槛触发**：仅当变动触及**跨模块/跨端架构边界或核心依赖增删、公开接口/持久化契约变更、并发锁/异步状态机重构、或新旧兼容层与旧模型退役清缴**时，才在本地编译测试通过后、交卷前**自主调用一次 `a8-judge`**（检出 `VIOLATED` 须修至 `PASSED`，`REQUIRES_APPROVAL` 向用户说明）；
   - **日常免检与禁重复增量复核**：单模块内常规功能增补、UI 展示/交互/筛选/文案调整、局部 Bug 修复、配置/测试/文档/规则与地图修改一律**免派发 `arch-judge`**（本地编译、单测与 `scripts/lints/` 过关即可交卷，除非用户显式调用 `/a8-judge`）；同一任务内通过后仅作局部微调时，**禁止再开新一轮增量复核裁决**。
   <!-- 2026-11-18: "arch-judge 增量复核裁决这个自动执行的频率有点高，稍微改一下东西就执行了；收紧为高架构风险门槛，常规局部改动与同任务微调免检" -->

## 四、 编码实施与工程卫生红线

- **缺陷分级与 YAGNI**：改码前评估频率 $F(1\sim10) \times$ 严重度 $S(1\sim10)$。**$F \times S < 10$ 仅记为已知边界，严禁改码**；不为无人问及的罕见边缘或假想未来做超前设计；疑似罕见边界先向用户说明风险与代价，点头后再加。
- **入口唯一校验 & 拒绝过早抽象**：外部输入只在入口校验一次并转定型值；只用一次的逻辑原地直接写，不提前抽象。
- **脚本统一用 Node.js**：新建脚本核心逻辑一律用 Node.js（`.mjs`/`.js`）放 `scripts/` 目录，不再用 `.ps1` 写业务逻辑；确需快捷入口时，`.cmd`/`.ps1` 仅作参数透传调用 Node.js。
- **终端编码 & 环境卫生**：Windows PowerShell 命令前统一前置 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8;`；测试日志统一放 `logs/`，临时测试文件验完即删；信息不足先查代码文档再提问，禁止猜测。
- **后台进程探测**：Windows 常驻服务须脱离前台启动（如 WMI `Win32_Process.Create`），启动后必查「PID 存活 + 端口/句柄就绪 + 延迟 2s 防闪退复检」，探测失败抓第一现场日志，严禁掩盖失败。

## 五、 双层文档体系与仓库地图治理（防 `AGENTS.md` 超 24KB 截断）

- **先读地图、渐进式加载**：动工前先读**实际被修改目标仓库**根目录的 `AGENTS.md`（跨仓查全局 `a8-agent-mind/repos.md`），按需先读命中的 **`docs/evergreen/` 常青文档**，仅在深挖背景或历史排障时顺回链按需打开 `docs/records/`，严禁一上来全量铺开历史流水账。
- **双层文档分域、术语表与尺度边界**：
  - **共享术语表 (`docs/glossary.md`)** — **跨层共用、在 `AGENTS.md` 引用**：作为 `docs/` 根目录唯一允许保留的跨层共享词汇表（常青文档与工作记录共用），每条术语用一句话普通话讲透物理含义并附代码/锚点；不在术语表中的非通用概念，由 Agent 自主决定补充入表或直接用普通话写清，严禁出现既未入表又未解释的自造词；
  - **常青文档 (`docs/evergreen/<domain>.md`)** — **高频主读、短小精悍**：只收单文件看不出来的跨模块/跨进程边界、非显而易见的状态机与不变量、共享 Schema/协议契约、生死阈值链路及 Fail-Closed/反直觉有意权衡与 `Reconsider when`；最硬红线前置，图+表+短断言替代长文，减法原地覆盖；禁复述源码细节、禁流水账、禁大段源码穷举、禁未落地设想；参考体量常规域 `2~6 KB`、核心引擎域 `6~12 KB`（严禁 `> 20,000 B`），无需元信息头，关键坑点内联挂回链指向 `../records/`；
  - **工作记录 (`docs/records/YYYYMMDD-<TYPE>-<MODULE>-<SUBJECT>.md`)** — **轻量复检与溯源**：仅在触及「架构权衡、系统边界/契约变更、深层根因排查」时按 [`templates/work-record.md`](../templates/work-record.md) 写入（4 项头 + 4 段精悍要点，每节默认 2～4 条要点，禁代码修改流水账；明确写清制约证据、被否方案、`Reconsider when` 及**已测与未覆盖边界**）；**常规局部改动与简单 Bug 走单测与自表达代码（仅非显而易见边界留简明 Why 注释），严禁滥建工作记录**；
  - **暂缓与废弃隔离**：未落地设想放 `docs/deferred/*.md`；后续设计推翻或更新既有记录时，只改旧记录 `- **状态**：` 与顶部横幅，不篡改历史正文。
- **隔离上下文整合 (`docs-curator`)**：写完工作记录或完成触及系统真相的改动后，由 `Stop` Hook（Decisions API 判定 `evergreen_sync_needed`）或主会话调用隔离上下文子代理 `docs-curator`，以**真实源码为最高事实源**（源码 > 工作记录 > 旧文档）核验并同步 `docs/evergreen/` 与 `AGENTS.md`。
- **根目录地图与容量红线**：根目录 **`AGENTS.md`** 直接挂接 **`docs/evergreen/` 常青文档索引表**（严控 **`< 20,000 bytes`** 防 Antigravity `24 KB` 截断），不再额外维护冗余的 `docs/INDEX.md` 中间索引；工作记录按需由常青文档回链渐进披露，或直接扫描 `docs/records/` 查阅。
- **标准目录与三层防线漏斗**：防线沉淀严格遵循 **确定性 Lint (`scripts/lints/*.mjs|*.py`) > 语义 Decision (`*.decision.json`) > 自然语言 Rule (`.agents/rules/` / `mind-rules.md`)**；UI 验证脚本入 `scripts/tests/ui-verify/`、产物落 `logs/ui-verify/`（不入库）。

## 六、 强制交卷检查（随会话自动闭环）

正式向用户汇报交付前，AI 必须自主确认全部过关：
1. **架构自检**：命中第三节高架构风险门槛的改动已完成 `a8-judge`（`PASSED`）；日常局部功能、UI、局部修 Bug 与文档改动免派发；
2. **双层文档与地图**：非平凡且需留档的改动已记入 `docs/records/`；触及系统契约/状态机/边界的已通过 `docs-curator` 对齐 `docs/evergreen/` 与核心 `AGENTS.md`（跨仓拓扑同步 `repos.md`）；常规局部改动无垃圾文档；
3. **质量门禁**：后端编译测试全绿、前端 `npx oxlint` 0 errors、项目 `scripts/lints/` 全绿、代码与常青文档严格一致。
