# 开发决策过程账本 (`a8-trace`)

Agent 干完活后的默认回复通常只写“改了什么、测试过了”这种**结果结论**，隐藏了真正决定代码质量的**过程取舍、弯路回退与风险边界**。本技能把整个开发决策过程还原成一张结构化、可审计、可追溯物理证据的 **TSV 决策账本**。

---

## 一、两种使用方式

1. **事后还原账本（默认高频）**：一轮功能开发、Bug 根治或重构刚结束，用户输入 `/a8-trace`（或“把刚才的决策过程做成账本给我看”），Agent 回溯本轮真实会话过程、当前 `git diff` / `git status` 与磁盘实测结果，生成账本并输出审阅视图。**事后还原模式严格只读，严禁借机修改任何业务源码。**
2. **事前开启边干边记**：开干前输入 `/a8-trace <任务>`，Agent 在开发途中每遇到一次关键设计分叉、否决备选、失败回退或实测结论，即实时向同一份 TSV 账本追加记录，收尾直接交账本。

---

## 二、固定 7 列 TSV 账本格式 (`logs/trace-<YYYYMMDD-HHmm>-<topic>.tsv`)

账本默认落盘在目标仓库 `<repo>/logs/trace-<YYYYMMDD-HHmm>-<topic>.tsv`（随 `logs/` 自动被 `.gitignore` 忽略，不污染仓库；仅当用户明确要求随提交附带审阅时才放入版本控制）。

| 列名 | 填写要求（平实大白话，禁空话） |
| :--- | :--- |
| `step` | 按真实时间顺序递增的序号（`1, 2, 3...`） |
| `stage` | 固定枚举：`摸底` / `设计取舍` / `实现` / `试错回退` / `验证` / `遗留风险` / `接力起点` |
| `decision` | 这一步具体做了什么判断、选了什么方案或排除了什么假设 |
| `alternatives` | 被否决的备选方案、尝试过但放弃的路线（无备选填 `-`） |
| `why` | 做出取舍或回退的**真实物理理由 / 实测数字 / 业务约束**（严禁事后编造） |
| `evidence` | 可核验的物理锚点：`file:line`、Commit SHA、实跑命令结论或 `logs/` 日志路径 |
| `status` | 固定枚举：`已采用` / `已回退` / `实测通过` / `未覆盖` / `待拍板` |

---

## 三、4 条铁律（防洗白、防幻觉、防注入）

1. **绝不美化弯路**：过程中试错失败、被证伪假设或被回退的改动，必须如实记为 `stage=试错回退`、`status=已回退` 并写清原因，严禁事后剪辑成“一次做对”的完美假轨迹。
2. **只追加、不篡改**：事前边干边记模式下，发现前序判断错误时只能追加新行声明推翻前一行，严禁回头删改历史行；多会话接手同一账本时，新增首行固定写 `stage=接力起点` 并注明前段范围与新会话标识。
3. **TSV 清洗与防表格公式注入**：写盘前清除单元格内的换行符与多余制表符（`\r`/`\n`/`\t` 改为空格）；任意单元格若以 `=`、`+`、`-`、`@` 开头（单独占位符 `-` 除外），写盘时必须前置英文单引号 `'`，防止用 Excel/WPS 打开时误触发公式执行。
4. **物理锚点逐条核真**：输出前必须核对每条 `evidence` 中提到的文件路径与关键符号在当前磁盘上真实存在、测试状态与实际跑过的一致；没测过的环境或边界必须显式记一条 `stage=遗留风险` + `status=未覆盖`。

---

## 四、交付呈现格式（落盘 + 对话直出）

1. **落盘 TSV**：将完整 7 列 UTF-8（无 BOM）TSV 写入 `<repo>/logs/trace-<YYYYMMDD-HHmm>-<topic>.tsv` 并给出可点击文件路径链接；
2. **对话内嵌审阅表**：
   - 决策记录 `<= 15` 行时，直接在回复中以 Markdown 表格呈现完整决策链（方便不切窗口直接审阅）；
   - 超过 `15` 行时，完整内容落盘 TSV，回复中只精选展示**所有「设计取舍 / 试错回退 / 遗留风险」关键行**；
3. **文末强制附 `重点审阅关注点 (Attention)`**：挑出 **1～4 条** 最值得开发者人眼重点复核的隐含假设、边界权衡或未测盲区（每条指向对应 `step` 与 `file:line`；确无隐患则直写“无明显风险关注点”）。
