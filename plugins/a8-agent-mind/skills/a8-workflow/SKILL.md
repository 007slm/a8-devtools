# A8 全生命周期工程工作流 (`a8-workflow`)

本技能为 `a8-agent-mind` 的单一工作流总入口，按任务类型把研发动作路由到 5 份场景指南，并把全局规则（[mind-rules.md](../../rules/mind-rules.md)、[TOKENS.md](../../rules/TOKENS.md)）、验证地图（`<repo>/docs/verify.md`）与双评审体系（[a8-judge](../a8-judge/SKILL.md)、[a8-dsh-review](../a8-dsh-review/SKILL.md)）串成统一交付顺序。

> **免开豁免**：一两行清晰修改、单一配置项调整、纯文档文字润色或直接技术问答，直接按全局规则改完并跑通局部校验即可，不必强行套用多阶段指南。
> **问路模式**：当用户不确定任务该怎么拆解（如输入 `/a8-workflow 我想做 X，怎么推进最稳？`）时，只给出推荐执行顺序与可直接发送的自然语言指令，不擅自改动代码。

---

## 零、 自主内化哲学：不用背一堆斜杠命令，说自然语言自动路由

遵循 `a8-agent-mind`「自主心智优先、拒绝命令碎片化」的设计初衷，原需手动串联的研发子动作均已内化进下方 5 份场景指南。除日常全流程自动串跑外，用户直接用一句话点名以下单项诉求时，也直接跳入对应指南章节执行完整多代理动作：

- **“上次干到哪了 / 恢复最近进度”** → 走 [long-task.md](guides/long-task.md) §5.2 & [analyze.md](guides/analyze.md) §1.2（锁本仓会话记录与当前 `git`/文档核实，输出四段现状胶囊）
- **“讲透这个模块怎么工作、当初为什么这么写”** → 走 [analyze.md](guides/analyze.md) §1.1 + §1.2（后台并行跑运行链路与 Git 历史两路只读子代理，分步递增画图讲透）
- **“改这里会影响什么 / 测一下爆炸半径”** → 走 [analyze.md](guides/analyze.md) §1.3（穿透协议/DB/原生编译盲区，写小脚本实跑验证安全前提并标 5 级确信度）
- **“先设计接口形状 / 开多方案擂台比选”** → 走 [feature.md](guides/feature.md) §1（至少 2 套所有权方案对比；高风险分叉开隔离目录并行实做、独立打分后手工融合亮点）
- **“清掉废话注释 / 写脚本实跑攻击这段改动找漏洞”** → 走 [feature.md](guides/feature.md) §5（派无护短包袱的独立只读子代理审注释并把警告转成类型/Lint，或隔离实跑击穿边界）
- **涉及页面/看板/组件样式重构或 Generative UI 卡片设计** → 自动叠加 [a8-ui-design](../a8-ui-design/SKILL.md)（按用户 Prompt 语义自动激活，无需用户手动调用）

## 一、 接单与路线对齐门禁

1. **复述目标与最小边界**：收到长篇、含噪或模糊工单时，动工前先用 2～3 句平实中文复述真实目标、完成判据与最小变更范围。有歧义或前提不对时立即核对，不带着猜测开工。
2. **挑战复杂路线（官方与极简优先）**：动工前先核对目标语言、框架或本仓是否已有官方标准方案或更简稳的做法。存在更简单方案时，按 [mind-rules.md](../../rules/mind-rules.md) 第一节直说一次理由与替代路线；路线确认后再推进，不重复反复询问。
3. **模糊诉求先深后大**：若用户希望先把粗糙念头改写成专家级高质量 Prompt 再开工，直接引导使用独立手动技能 [`/a8-prompt`](../a8-prompt/SKILL.md)（不改代码，输出专家 4 问与改写版 Prompt 停步交付）；已确定直接推进时，能靠 1 个小实验定夺的技术分叉直接走隔离原型实测，不在嘴上空议。
4. **切话题重置路由**：在同一会话中切换到新任务或新问题类型时，立刻重新走下节路由表选定场景指南，防止上一份指南的约束或惯性带偏当前工作。

## 二、 五大场景指南路由表

命中指南后，**第一步将所选指南的关键执行步骤写入会话待办列表**，再逐项推进；引用某条工程原则改变了当前设计取舍时，顺手点明它改变了哪一个具体决定。

| 任务场景 | 命中场景指南 | 核心边界（一句话禁区） |
| :--- | :--- | :--- |
| **查原理、追历史动机、评估爆炸半径、活进程或离线剖析取证、问题分诊** | [guides/analyze.md](guides/analyze.md) | 严格只读，**严禁改动业务源码** |
| **缺陷复现与根治、核验已有修复、连续修不动时的前提排查** | [guides/bug-fix.md](guides/bug-fix.md) | 先查已有修复，真实表面独立复现 2 次再修 |
| **单次慢点排障、多轮指标调优、所有耗时与吞吐对比实验** | [guides/perf.md](guides/perf.md) | 无基线严禁优化，数字必过防伪 7 问 |
| **新功能、跨边界改形、状态机建模、纯重构、隔离原型、像素级 UI 对齐** | [guides/feature.md](guides/feature.md) | 先定数据形状与状态不变量，再写业务逻辑 |
| **跨阶段计划、多代理并行隔离、无人值守循环、安全暂停、冷启动续跑、工作区清理** | [guides/long-task.md](guides/long-task.md) | 写者物理隔离，结果与进度只认磁盘实测副作用 |

## 三、 通用工程纪律与上下文防火墙

1. **证据与引用标签**：只陈述亲眼读过的源码路径、真实符号名、命令输出与文件行数；汇报关键结论时逐条标明 `[实测]`、`[推断]` 或 `[待确认]`，严禁拿源码推演或旧记忆冒充实测结果。
2. **先查目标仓验证地图**：任何改码任务开动前，必须先读目标仓库根目录 `AGENTS.md` 与 `<repo>/docs/verify.md`（若存在），明确所改模块必须穿透的真实运行表面、物理判据与本地环境盲区；编译通过或仅 Mock 单测绿灯不算过关。
3. **小步验绿与脚本工具复用**：
   - 多步改动或批量清理按“已知绿态 → 单一步骤修改 → 立即跑对应校验转绿 → 再动下一步”推进，严禁攒到最后集中排错；
   - 遇跨多文件的同类改造或重复核验，先手工跑通 1 个样本，再写一个可重复运行的校验或处理脚本，以脚本实跑结果作为交付凭据（不要把长步骤只留在口头描述里）。
4. **子代理与 `swarm` 派发契约**（对齐 [TOKENS.md](../../rules/TOKENS.md)）：
   - 大段报错日志、全仓检索、全量单测与剖析转表统一交给隔离子代理消化，主会话只接收结构化结论、`file:line` 与产物路径；
   - 派发首行必须写明必读地图指针（目标仓 `AGENTS.md`、`docs/verify.md`）、具体负责范围、禁止修改的文件与明确完成条件；若允许其继续派发下级代理，须将此规范一并传递；
   - **写入物理隔离**：只读探索与审阅保持 `inherit`；多个写入者并行修改时，必须通过 `swarm` 的 `workspace:"share"` / `"branch"`、独立 `git worktree` 或 `CowFS` 隔离工作区（严禁两方同改一个文件或同一份 JSON 配置）；
   - **默认新建干净子代理**：修补轮、换向重试或下一独立队列项，默认新建干净子代理（附原任务目标与上轮报告指针）防止脏上下文干扰；仅当本地保有昂贵未提交中间态或运行中进程时才复用原会话。主会话须亲审所有子代理的 Diff 并独立撰写交付总结。
5. **可逆先干与停步请示边界**：
   - 当技术路线已对齐、不属于 $F \times S < 10$ 罕见边界（见 `mind-rules.md` 第四节）、不涉及 `/a8-improve` 规则落盘且操作可撤回时，直接推进编码与验证，用实测结果汇报，不用“要不要我做 X”反复打断用户；
   - 遇到不可逆操作（删除数据、强推共享分支、发版部署、外发消息）、路线挑战尚未拍板、缺少运行环境或凭证、或纯交互与产品偏好取舍时，明确停步交由用户决定。

## 四、 A8 统一交卷收口

代码作者的自报与编译绿灯均不等于验收通过。所有非只读任务交付前，统一按以下 5 步收口：

1. **注释清查与汇报去水**：对照 `guides/feature.md` §5 注释白名单清理多余解释、过时注释与“临时/兼容/别删”借口注释（发现真实硬约束先升级为类型、单测或静态检查）；交卷文字去掉 AI 空话套话与未入 `docs/glossary.md` 的黑话，一概念只用一个词，先写前提条件再写结果或命令。
2. **仓内门禁与真实表面全通**：跑通目标仓库 `AGENTS.md` 规定的编译、单测、`scripts/lints/` 机械检查，以及 `<repo>/docs/verify.md` 命中的真实运行表面；涉及用户界面改动或验收的按 [a8-ui-verify](../a8-ui-verify/SKILL.md) 执行并将截图与报告落盘 `logs/ui-verify/`。
3. **高风险按门槛终审（免高频增量复核）**：仅当改动触及跨模块边界、公开或持久化契约变更、并发锁或状态机重构、或旧模型退役清缴时，才自主调用一次 [a8-judge](../a8-judge/SKILL.md)（常规局部功能、UI 调整、局部修 Bug、文档修改及同任务微调一律免检）；遇跨文件复杂状态机或用户明确要求时，执行 `/a8-dsh-review`（2～3 轮上限 + $F \times S < 10$ 熔断）。
4. **双层文档与地图同步**：常规局部改动与简单 Bug 修复不写工作记录；触及架构权衡、边界契约或深层根因时，按 [templates/work-record.md](../../templates/work-record.md) 写入 `docs/records/YYYYMMDD-...md`，并**直接在当前上下文**顺手轻量化同步 `docs/evergreen/`、`docs/verify.md` 与根目录 `AGENTS.md`（**严禁**为此额外启动 `docs-sync` 子代理；每晚 20:00 定时任务与 [docs-sync](../../agents/docs-sync.md) 慢轨会自动全量审计补齐）。
5. **输出 40 行以内高密度交卷简报**：主回复控制在 40 行以内，按以下顺序组织（空白项直接省略）：
   - **目的**：解决什么问题或达成什么边界；
   - **改动点**：核心文件与真实符号变化；
   - **覆盖范围**：本次包含与明确排除的模块；
   - **否决的替代方案**：只写审阅者必然会追问的权衡（不罗列显而易见事项）；
   - **影响面与未测边界**：可能波及的上下游及本地环境未覆盖限制；
   - **实测验证结果**：原样贴出关键命令结论与实测数字；冗长日志、完整测试输出与对比表格一律写入 `logs/` 并在简报附上文件路径。
