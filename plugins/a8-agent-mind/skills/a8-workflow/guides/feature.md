# 指南 4：新功能开发与纯结构重构 (`feature`)

> **适用场景**：新功能开发、跨边界接口改造、并发/状态机设计与纯结构重构。  
> **硬红线**：**先定数据形状与不变量再写业务逻辑；重构禁夹带新功能；收口必过注释清理与真实运行面验绿。**

---

## 1. 新功能与跨边界改造
1. **第一性重设计追问**：先顺调用链摸清上下游影响面；接入新需求时自问“第一天就有此需求会怎么设计”，拒绝在旧烂设计上反复打补丁。
2. **跨边界先思考接口形状**：跨模块或公开接口变更前，先在设计阶段快速权衡 2 套类型/签名/所有权思路，选定“每块状态只有一个主人、调用方需知最少、纯逻辑可抽纯函数”的一版直接实现——**严禁自动在磁盘建多份原型或拉多子代理做交叉实做对比**（仅用户显式要求对比时才做）。
3. **先定数据形状、强类型与幂等状态**：
   - 用枚举/判别联合替代散落可选字段袋并做穷尽检查；同基础类型不同语义用包装类型在构造边界一次校验；
   - 外部输入（JSON/RPC/CLI/DB）仅在系统入口定型解析，内部直接信任类型；有权威 Schema 直接派生不手写副本；
   - 状态步骤按当前物理态差量收敛保幂等，锁/半写入产物用临时文件加原子重命名替换；高并发/协议状态机绝不靠脑推画假图，可按需调用 [`/a8-statechart`](../../a8-statechart/SKILL.md) 跑零依赖 BFS 穷举与 Mermaid 出图（或用仓内已有 `.qnt` 模型/随机序列单测做“破坏抓虫验证”，变更源码同步核对模型漂移）。
4. **仅限后端的务实 TDD（前端完全不需要，禁假 Mock）**：
   - **仅限后端（优先先红后绿）**：编写后端纯逻辑/算法、解析器/协议编解码、校验规则、状态机流转或核心接口，且存在低成本本地单测路径时，先写聚焦外部契约的最小失败测试 → 确认红灯 → 写实现转绿（遵循 [bug-fix.md](bug-fix.md) §4 双反证防假测，不死绑私有实现）；
   - **前端完全免 TDD（驱动/硬件薄壳与胶水脚本同理）**：前端代码（页面、组件、交互与样式）**完全不走 TDD**，严禁为凑覆盖率造前端测试或脆弱假 Mock，直接通过类型/构建门禁（`tsc`/`oxlint`/`build`）与最小真实运行表面验真。
5. **同波次迁移**：按「底座桩 → 分支实现 → 全调用方同波迁完并立即删旧入口」逐单元验绿推进，严禁留未批准的新旧兼容层。

## 2. 纯结构重构（只改结构，严禁改行为）
- **剥离功能与修 Bug**：重构途中发现缺陷或缺失功能单独拆任务，先按原契约收口结构。
- **先立行为锚**：动结构前先跑通锁定现行行为的特征测试或输出对比脚本（仅编译/Lint 绿不算行为锚）。
- **先减后加 + 唯一保留判据**：先删死代码、内联单调用包装、清掉护旧细节的死测试；对照 `docs/verify.md` 跑旧/新输出等价验证。**若未切实降低读者理解负担（30 秒内看清状态从哪来、谁能改），整块回退。**
- *(仅当存在靠跑一次实测就能拍板的高分叉交互/时序问题时，可在隔离 `scratch/` 速成丢弃式原型对比，拍板后彻底作废按正式规范重写，严禁合入草稿。)*

## 3. 注释白名单自查与交卷收口
1. **5 类注释白名单（主会话直接自查 Diff，不额外自动起审查/对抗子代理）**：
   - **仅允许保留**：① 版权/许可证头；② 外部依赖/OS/协议强加的不可改怪异限制；③ 规则确有缺陷的样式 Lint 豁免；④ 对外公开 API 文档注释；⑤ 代码本身表达不出的关联 Issue 或 `docs/records/` 链接。
   - **一律删除或改码根治**：叙事分隔条、复述函数名的翻译注释、死代码、`TODO/临时/别删` 自保说辞（查 `git log` 若约束仍成立则升格为类型/单测/Lint 再删注释）；**遮掩真实 Bug 或安全问题的 Lint 抑制必须连隐患一起根治**。
2. 执行 [SKILL.md](../SKILL.md) §4 收口（涉及界面改造自动遵循 [a8-ui-design](../../a8-ui-design/SKILL.md)；浏览器 UI 验收仅在用户主动敲 `/a8-ui-verify` 时跑；提交走 `/a8-commit`）。
