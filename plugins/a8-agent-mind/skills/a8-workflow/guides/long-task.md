# 指南 5：跨阶段计划、无人值守循环与断点续跑 (`long-task`)

> **适用场景**：需分期审批的跨模块大工程、基于 `schedule` 的无人值守循环、安全暂停与冷启动续跑。  
> *(注：日常开发完成后生成可审阅的 TSV 决策过程账本，请直接使用独立技能 [`/a8-trace`](../../a8-trace/SKILL.md)。)*

---

## 1. 跨阶段计划（1～2 文件简单改动免写计划）
交付人工审批的跨阶段方案须包含 4 要素：
1. **可证伪完成谓词**：明确什么客观实测全部成立才算完成（高风险节点加检验门禁）；
2. **依赖与独占文件清单**：风险最高的不确定验证排最前，标明阶段依赖与各自独占文件边界；
3. **验证基线先行**：先落对比测试桩与改前基线，再动业务代码；
4. **每阶段验收契约**：列清局部单测、`<repo>/docs/verify.md` 对应真实表面与失败红线。

## 2. 进度监工与门禁纪律
- **固定回报与按磁盘监工**：拆分子任务时带基准 SHA、可执行命令与固定回报（`PASS` / `ISSUES` / `BLOCKED` + `file:line`）；判断任务是否卡死**不轻信口头“运行中”，只认磁盘文件改动、本地提交或日志时间戳**，长日志写入独立文件不回灌主会话。
- **禁私自软化门禁**：任何环节提议放宽断言、调高容忍或加白名单，须附独立验证实跑证据并经人工批准。

## 3. 无人值守循环、安全暂停与冷启动续跑
1. **小步实验循环（`schedule` / 后台唤醒）**：每轮只做最小证据支持的一步 → 实测退出谓词 → 确实推进且不破门禁才留用，**无推进或失败整步回退**；**严禁为宣布胜利偷偷放宽完成谓词**。途中可逆挡路小错就地修完回主线；遇不可逆操作或死胡同停步汇报（首句报待拍板项，未实测完严禁标“已完成”）。
2. **安全暂停（仅用户喊停触发）**：停在原子边界、撤回半成品、关停空闲子代理、不做不可逆动作，写清分支状态与下一步第一动作。
3. **冷启动续跑**：先读 `logs/trace-*.tsv`（若有）、本仓最近聊天记录与 `git log`/`git diff` 还原现状；**信任前任已落盘调查，但对前任声称“已完成”的交付项须在真实表面复核一遍再接力**。清理冗余工作区前确认「已合入/废弃 + 未提交改动为 0 + 无活跃会话引用」，有未提交改动必停步人工确认。
