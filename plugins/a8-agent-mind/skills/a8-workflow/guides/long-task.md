# 指南 5：跨阶段计划、无人值守循环、安全暂停与工作区清理 (`long-task`)

> **适用场景**：没有单一场景指南能一次包圆的多阶段大工程、需要人审后再跑的跨模块分期计划、基于 Antigravity `schedule` 的无人值守自动推进、多代理并发写协调、安全暂停与冷启动续跑、以及多工作区安全清理。

---

## 一、 跨阶段立框与方案规划

1. **免方案边界**：只改 1～2 个文件且实现路径直接了当的任务，跳过方案书直接按 [feature.md](feature.md) 或 [bug-fix.md](bug-fix.md) 开干。
2. **不确定技术分叉先原型**：靠跑一个小原型能实测拍板的，先按 `feature.md` §3 跑完原型定案；只向用户请示靠实验定不了的产品或主观体验取舍。
3. **长程方案书必备 4 要素**（交付给人审阅，收到明确开跑指令再动生产源码）：
   - **可证伪完成谓词 + 风险定级**：明确写出什么客观实测结果全部成立才算做完；不可逆动作与高影响面节点提级加检查门槛；
   - **依赖图、并行边界与独占文件清单**：风险最高的未知技术验证排最前面；写清阶段先后依赖、哪些单元可以并行、以及每个并发单元**独占可写的文件范围**；
   - **先搭验证基线后改业务码**：把对比测试桩与变动前基线先落地，确保后面每步对比是“旧值与新值”；
   - **每阶段三证齐全**：每个独立交付单元必须同时列明「局部单测 + `<repo>/docs/verify.md` 真实运行表面场景 + 性能基线与失败红线」，缺一不算完成（涉及交互改动的标明需人工审定后再并入）。

---

## 二、 并行写隔离、多代理调度与物理副作用监工

1. **写隔离与派发契约**：
   - 多个写入者同时推进时，强制使用 `swarm` 的 `workspace:"share"` / `"branch"`、独立 `git worktree` 或 `CowFS` 隔离工作区；各自将长日志写入独立小文件（不回灌主会话）；严禁多代理混改同一文件或同一 JSON 对象的不同字段；
   - 发多路并发前写清评判规则（首个通过 / 全部打分 / 择优合并），每个工单必须带目标、基准 Commit SHA、可执行命令与固定回报格式（`PASS` / `ISSUES` / `BLOCKED` + 真实 `file:line`）；缺关键实证的工单只重派一次。
2. **按物理副作用判定是否卡死**：
   - 协调者检查长跑子代理时，**不轻信口头“正在运行中”**，只认磁盘文件改动、本地提交记录、测试产出或日志时间戳是否有新变化；
   - 遇到持续报错、无写入权限或超过合理耗时仍无任何磁盘新副作用的子代理（处于等待上游/人工审批者除外），立即更换干净新代理顶上并回收故障工作区。
3. **禁私自软化门禁**：任何代理提出调高错误容忍、放宽断言、加入白名单或关闭某项静态检查时，必须附上独立验证方的实跑证明，并经协调者复核同意（或涉及主流程完成标准的须由人工批准），严禁悄悄放松门禁求绿灯。

## 三、 无人值守循环（Antigravity `schedule` / 后台任务）

1. **定时或事件唤醒**：利用 Antigravity 原生 `schedule`（定时轮询或等待子任务/通知唤醒，不靠空循环占用配额）驱动多轮推进；明确每轮盯哪个客观退出谓词。
2. **单步最小实验循环**：
   - 先锚定机器可直接判定的退出谓词；
   - 每轮只改最小证据支持的那一步 → 在真实产物上实测校验（如果一次过得过于轻松，先怀疑验证脚本本身是不是写漏了）→ 确实推进且不破坏门禁才保留并记录；**无推进或失败则整步彻底回退**（绝不留“也许有用”的半截补丁）；
   - 途中发现挡路的小问题（坏脚本、坏测试桩、衍生小错），就地按规矩修好记账后再回主线，不拿可逆小事打断人工；唯有遇到不可逆操作、真实产品取舍或无法突破的死胡同时才停下汇报。
3. **严禁放宽完成谓词宣布胜利**：遇平台期就更换思路、拆分阶段或重新剖析现场；确属无解死胡同时如实停步摆出卡点与已试路径，**绝不允许偷偷修改或放宽最初约定的完成谓词**。

## 四、 过程审计账本 (`logs/<task>-decisions.tsv`) 与长任务进度汇报

### 1. 审计账本 (`logs/<task>-decisions.tsv`)
长程与无人值守任务必须维护 1 份只追加、单行记录的 TSV 审计账本（默认归入 `.gitignore` 覆盖的 `logs/`，仅大型交付需要外部审查时随提交附带）：
- **固定 6 列**：`ts`（ISO8601 时间） | `phase`（阶段或工作线） | `decision`（选了或做了什么） | `why`（大白话理由） | `evidence`（Commit SHA、`file:line`、产物或截图路径，不写长文） | `result`（实测状态，如 `tests green` / `reverted` / `INCONCLUSIVE` / `open`）。
- **4 条防伪与卫生纪律**：
  1. **只追加不篡改**：发现旧判断有误，新增一行声明纠正并覆盖前一行，严禁删改历史行；
  2. **清洗分隔符与防公式注入**：写入前剔除单元格内的换行和多余制表符；若单元格以 `=`、`+`、`-`、`@` 开头，必须前置英文单引号 `'`；
  3. **多会话续写标 `start`**：每当新会话或新代理接手已有账本时，第一行固定写 `phase=start`，`decision` 标明接管前已有行的时间范围，`evidence` 标明本代理/会话 ID（`start` 只作跨段分隔，不作他用）；
  4. **交卷前双核对**：收口前先对照当前会话 `transcript.jsonl` 与磁盘真实文件核对每条证据是否真实可打开、有无漏记的关键分叉或回退，再派 1 名**未参与写码的独立审查者**扫一遍账本与轨迹，在交付末尾输出 **`Attention` 风险点清单**（首行标明 `reviewed by <角色/模型>`，逐条指向具体行号或隐患，无隐患写“无风险项”）。

### 2. 长任务进度汇报格式（用户离开后回来查看进展）
只读汇总（不借汇报时机改码或启动新任务），按以下顺序输出让用户看一条消息就能拍板：
1. **开篇第一句**：先点明现在有什么事卡着等用户拍板（全部无需拍板则直说“当前无待拍板阻塞项”）；
2. **图先于文 + 真实条目状态**：先内嵌最新截图或简明架构图（不编造未实采的图），再按用户原有关注项逐条用大白话报真实状态——**任何仍在等拍板或未实测完的事项，严禁标记为“已完成”**；
3. **待拍板清单一次给齐**：每个待用户决定的事项列清：**需要拍什么 → 对比选项（各自好处与代价） → AI 推荐选项与实测依据 → 明确风险（哪怕低风险也说明白）**。

## 五、 安全暂停、冷启动续跑与工作区安全清理

### 1. 安全暂停（仅在用户明确要求暂停时触发）
收到“先停一下 / 暂停”才执行（若用户说“别停 / 通宵继续”则绝不中断）：
1. 在安全原子边界停下：收尾或干脆撤回当前最小未完修改，关停全部空闲子代理，不再开新工单，**绝不在暂停时发起任何不可逆动作**；
2. 保留磁盘工作状态：将未提交改动妥善暂存在当前工作分支（如树是坏的在备注写清），并写出冷启动续跑备忘（目标、当时正做什么、已验过什么、当前分支/磁盘状态、下一步第一动作、关键文件路径与坑点；**若已有 `decisions.tsv` 直接指明路径不重复抄写**）；
3. 简短汇报：说明停在循环哪一步、哪些文件已落盘、工作区是否干净以及恢复后的第一个具体动作。

### 2. 冷启动续跑（把前任轨迹当权威起点）
接手旧会话或中途停掉的任务时：
1. 先读 `logs/<task>-decisions.tsv`、当前目标工作区最近 `transcript.jsonl`（严格锁定当前工作区，禁跨无关项目目录翻找）以及 `git log` / `git diff` 还原分支、工作区与待办全貌；
2. **信任前任已落盘的权威记录**：不要从头重新复现前任已查实的问题，也不要重做已合入的工作；
3. 路由到对应场景指南继续推进前，**必须针对前任声称已完成的交付项在真实运行表面核验一遍**（前任口头自报不等于真通过），确认无误后精准从断点接力。

### 3. 工作区安全清理门禁（防误删未提交成果）
清理冗余 `git worktree`、`CowFS` 挂载目录或大体积构建缓存前，先做全盘盘点：
1. **先盘点再动手**：枚举 `git worktree list` 与 `cowfs` 挂载路径（不靠手猜目录名），对每个工作区统计 5 项：**占用空间、相对主干分支是否已合入、已追踪文件未提交修改数 (`wip:N`)、未追踪杂物文件 (`scratch:N`)、以及是否仍被置顶或活跃会话（含子代理）引用**（通过子代理后台扫描会话目录确认）；
2. **分级执行清理**：
   - **仅当同时满足“分支已合入（或明确废弃） + `wip == 0` + 无任何活跃会话引用”** 时，自动移除对应工作区/清理目录并列明顺带清除的 `scratch:N` 杂物文件；
   - **只要存在 `wip > 0` 未提交修改或仍被活跃会话引用**，**强制停下展示 Diff 并交由人工确认**后再删（删除 `wip` 是不可逆数据丢失）；
3. 清理后复核磁盘空间前后对比、已删清单与每个保留目录的一句话保留原因，并确保遵循 `SKILL.md` §4 完成最终交付收口。
