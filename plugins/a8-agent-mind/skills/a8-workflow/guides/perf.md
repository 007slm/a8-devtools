# 指南 3：性能排障与指标调优 (`perf`)

> **适用场景**：**仅在用户明确要求**排查慢点/退化或做指标调优与基准对比时启用（日常开发严禁 AI 擅自自动跑耗时压测或多轮交叉对比）。  
> **硬红线**：**无可靠实测基线严禁动手优化；严禁靠读源码猜瓶颈。** 跑数前先查 `<repo>/docs/verify.md` 性能基准规范。

---

## 1. 基线与剖析严格分离 + 7 级廉价优先阶梯
1. **基线与剖析分开跑**：先在纯净生产配置下测出改动前基线（须过下文防伪 7 问）；再另跑一轮独立剖析（CPU / 内存分配 / GC / I/O / 锁竞争）锁定真正限速器与 `file:line`。**严禁把剖析轮数字当正式成绩。**
2. **由廉到贵 7 级排查（前级达标即止）**：① 删无用功 → ② 同生命周期只做一次 → ③ 缩窄扫描/裁剪列/减拷贝 → ④ 延后非关键路径工作 → ⑤ 异步移出主链路 → ⑥ 物理拆片并发（先拆共享再谈锁）→ ⑦ 换算法/存储结构/批协议。
3. **每改一步同面复测**：确保功能 0 破坏、提升跨过轮间波动再留用。

## 2. 多轮指标调优纪律（需迭代压榨指标时）
1. **锁死双停步谓词与冻结测试桩**：同时定死「目标阈值 + 最低尝试轮数」，并写死带 `errors == 0` 断言与实际工作量计数的测试桩，过防伪 7 问后**全程冻结，严禁调松测试桩**。
2. **单变量试错与实验记录**：每轮只验 1 个绑定具体代码机制的假设，记入 `logs/<task>-perf.tsv`（`id | hypothesis | change | before | after | delta | tests | verdict | note`；有统一账本如 `logs/test-history.jsonl` 一并写入）。功能回归全绿且明确过噪声带才保留，其余整步回退。
3. **正确性与简洁度高于数字**：破坏功能提速十倍也必须回退；遇平台期切换优化大类或重做剖析。

## 3. 强制门禁：性能基准防伪 7 问（缺关键项判 `INCONCLUSIVE`）
汇报任何对比数字前必须实证回答（粗略摸底标明“单次摸底”但仍必查 4、7 问；技术选型严禁单跑 1 遍）：

| # | 核查问题 | 反作弊实证要求 |
| :---: | :--- | :--- |
| **1** | **瓶颈限速器在哪？** | 用独立剖析轮抓到的热区与 `file:line` 说明（兼查压测发端是否先打满），禁靠读源码猜。 |
| **2** | **两边都按生产配置调优了吗？** | Release 编译、生产 JVM/引擎参数、批大小、索引与预热起点对齐，不拿默认参数比调优版。 |
| **3** | **有无违背物理/算术上限？** | 用磁盘/网络带宽、CPU 核数与改前占比验算，超上限必有漏算工作。 |
| **4** | **错题数是否等于 0？** | 脚本强制断言 `errors == 0` 并校验落盘行数/结果实质正确（异常早退极快）。 |
| **5** | **稳定可复现吗？（5+ 次 A/B）** | `A, B, A, B...` 交替跑 ≥5 轮，报中位数与最小～最大区间；小于波动即判无显著差异。 |
| **6** | **真实端到端占比多大？** | 微基准旁并列真实数据规模端到端成绩，防局部提速对整体无效。 |
| **7** | **工作真的发生在计时区内吗？** | 确认请求打进服务端、结果落盘或消费完；防惰性流未拉取、异步未等完、DCE 或命中旧缓存。 |

> **强制 `INCONCLUSIVE` 判据**：指不出限速器、存在未调优对照边、或未核查第 4/7 问 → 一律判 `INCONCLUSIVE` 并列明缺口。主回复仅报核心数字、限速器 `file:line` 与日志路径。
