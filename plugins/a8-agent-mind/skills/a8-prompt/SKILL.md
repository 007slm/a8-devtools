# 提示词深化与重写 (`a8-prompt`)

本技能仅在**用户主动希望把一个粗糙想法打磨成高深度、可执行、防跑偏的 Prompt** 时使用（例如攻克陌生领域难题、启动重型性能调优、或在发起 `/plan` / `/swarm` / `/goal` 之前打磨任务书）。

> **两条铁律**：
> 1. **只挖深、不扩范围（Deeper, Not Bigger）**：严禁借优化提示词之名往需求里塞额外功能、过度设计或假想需求；全部深度只往“根因、最原始一手数据、实测原型、客观验真标准”上挖。
> 2. **改写完立即停步（Rewrite Then Stop）**：本技能**绝不修改任何仓库文件或直接开始写业务代码**；把改写好的高质量 Prompt 交给用户审阅，由用户决定微调、直接回复“按这版执行”，或复制发给 `/plan` / `/swarm` / `/goal`。

---

## 执行步骤

### 第 1 步：轻量贴合当前仓库真源（防纸上谈兵）
- 若当前处于具体项目仓库中，先快速瞄一眼目标仓库根目录的 `AGENTS.md` 与 `docs/verify.md`（若存在，最多 1~2 次只读操作，**不做全仓大扫荡**）；
- 目的是让后续推荐的“一手数据源、测试工具与客观验真标准”直接命中该仓库现成的真实脚本、日志、端口或模型（例如 `a8-turbo` 的 `CdcPipelineBenchmarkIT`、`test-recorder`、`:1059`、Quint `.qnt`），绝不凭空编造项目里根本不用的外部工具。

### 第 2 步：重写前先回答 4 个专家级问题（直白简短，每条 1~3 句）
针对用户给出的原始想法或草稿 Prompt，先输出以下 4 点分析：

1. **顶尖行家还会做哪件你没提的关键事？**
   指出在这个领域真正有经验的资深工程师会先确认或额外把关的核心动作（只挖深，不加新特性）。
2. **最原始的一手材料在哪？**
   指出应该直接从哪份未经加工的原始数据、协议报文、运行剖面、真实日志或核心源码起步，而不是只看二手总结或抽象封装。
3. **会动用什么具体方法与工具？**
   给出落地到位的排查/建模/测量方法与具体工具（优先复用本仓已有脚本与验证面）。
4. **除了你和我的主观判断，什么客观事实能证明结果做对了？**
   给出可证伪的外部验收标准（具体实跑命令输出、前后对比指标、物理表结构比对、端到端实测现象等，拒绝“看起来更好”这类主观词）。

### 第 3 步：输出改写后的高质量 Prompt 并立即停步
- 将上面 4 点的结论自然融合成一段结构紧凑、可直接复制发送的 **「优化版 Prompt」**（放在 Markdown 代码块中方便一键复制）；
- **分叉与边界处理**：
  - 凡是靠跑一个小实验或隔离原型就能分出高下的技术分叉，在改写后的 Prompt 里明确要求 AI **先做实验/原型，再基于实测现象给出推荐选项**；
  - 凡是实验定不了的产品取舍、交互偏好或不可逆范围抉择，明确标注 **留给用户拍板**；
- **交付后立即停步**：简短提示用户“可以直接回复「按这版执行」，或复制给 `/plan` / `/swarm` / `/goal` 启动”，严禁抢跑动手改码。
