# 通用架构黄金红线与质量门禁规范 (Universal Architecture Redlines)

本规范为所有接入项目的通用架构黄金红线基准。由 `arch-judge` 插件在开发与提交期自动执行语义裁决。

---

## 1. 演化契约与零擅自向后兼容红线 (Zero Unauthorized Backward-Compatibility)
- **极简演化哲学**：严禁未经批准的向后兼容逻辑。包括为照顾旧版本、历史客户端而私自保留的废弃类、废弃接口、过渡层、过渡方法、双轨分支或隐式兜底。
- **物理删除优先**：旧模型退役或被新架构取代后，旧代码必须物理连根拔起删除，绝不以“为了向后兼容更稳妥”为由私自保留历史包袱与死代码。
- **显式审批豁免**：只有经系统架构师与用户明确审批批准保留的兼容能力，方可保留，且必须有明确的生命周期退役截止时间与关联 ADR 文档。

---

## 2. 系统边界与纯净隔离红线 (Topology & Boundary Isolation)
- **纯净客户端驱动零框架侵入**：无侵入式客户端 SDK、JDBC 代理驱动严禁依赖 Spring Boot、Netty、Jackson、HikariCP 等重型服务端容器类库，严禁引入 ClassLoader 冲突。
- **单向严格分层**：模块间必须遵循严格单向依赖，底层纯工具/公共库（如 commons, license）严禁反向依赖上层业务服务或应用进程宿主。

---

## 3. 并发安全与热路径性能红线 (Concurrency & Hot-Path Performance)
- **热路径零大粒度排他锁**：高并发数据面读取热路径（如 Cache / Store / Buffer）严禁在方法签名上声明 `synchronized`，必须使用细粒度锁或无锁并发结构（如 ConcurrentHashMap / DCL）。
- **零幽灵轮询与事后探测**：严禁在请求流水线或心跳监控中增加跨线程、跨数据源的反查探测与隐式防抖。事实必须由显式事件流或上游第一现场驱动。

---

## 4. 实现规范与错误现场保留红线 (Implementation Hygiene & Single Path)
- **核心能力单一实现路径**：同一核心领域能力（如 SQL 解析、数据转换）在全工程只允许存在唯一定义路径，严禁引入双轨手写解析器。
- **错误物理现场绝对保留**：未处理的异常严禁使用 `try-catch` 静默吞掉并返回默认空值，必须保留异常堆栈并记录上下文；所有日志必须统一采用日志门面（如 SLF4J）。
