# Architecture & Workflow Improvement (`arch-improve`)

本技能专用于在**开发任务收尾（Session Wrap-up）阶段**执行架构测绘与资产归档。其核心定位是**项目架构测绘师（Cartographer）**：重点确保大地图准确导航；对新增规则保持极度克制，严防规则库膨胀。

---

## 核心设计与执行铁律

1. **地图绘制是主线，规则新增是例外 (Map First, Rules by Exception)**：
   - **核心职责（80%+）**：绘制与校准双层大地图体系：
     - **项目内大地图 (`AGENTS.md`)**：负责单工程内部的模块分层、关键入口、调用契约与长期 SPEC/ADR 索引；
     - **宿主机全局拓扑 (`agent-mind/projectMap.md`)**：负责开发机全量项目的全局生态位定位（核心生产 `core`、辅助工具 `tooling`、测试靶场 `test-bed`）与跨项目协作关系；
   - **规则提炼的极高门槛**：只有当会话中出现**用户反复强调（>=2次）、或者模型多次踩坑屡教不改**的顽疾时，才允许提炼 1 条极简硬规则；偶发小 Bug 或单次沟通偏差，**严禁借机新增规则**。

2. **绝对在主会话中运行（No Subagent）**：
   - 严禁启动 Subagent！复盘测绘的原材料（代码改动、接口调整、调用链路、人机交互）天然存在于当前主会话的完整上下文中。
   - 在当前会话直接执行，零进程开销、零延迟，且不影响任务收尾后的会话生命周期。

3. **人机协同确认机制（Human-in-the-loop）**：
   - 生成的地图更新或规则草案必须以 **Draft Diff** 形式呈现；
   - **严禁擅自静默修改**项目中的 `AGENTS.md` 或规则文件，必须由工程师审阅、点头后方可落盘。

4. **强制配合 Generative UI 紧凑型卡片**：
   - 必须生成高颜值、高信息密度的 HTML 卡片并通过 `<agent-embed>` 内嵌呈现，让工程师一眼抓取本次测绘的核心产物。

## 执行流水线 (Execution Pipeline)

### 步骤 1：扫描会话第一现场与改动事实
综合分析以下信息源：
- **物理改动事实**：改了哪些模块？是否新增了路由、命令、配置文件或端口？
- **调用拓扑演变**：模块间依赖关系是否发生变化？是否存在新的跨模块契约？
- **长期文档产出**：是否沉淀了新的 SPEC、ADR 或架构设计文档？
- **人机交互轨迹**：用户在对话中是否存在**反复多次强调、纠偏**的痛点问题？

### 步骤 2：生成双层测绘产物
1. **大地图同步补丁（Map Sync Draft，核心主线）**：
   - **工程内地图**：给出项目根目录 `AGENTS.md` 的更新 Diff（模块职责增补、关键入口标注、文档索引挂号）；
   - **全局项目地图**：若本次任务引入了新工程、调整了跨项目依赖或变更了测试靶场，同步给出 `agent-mind/projectMap.md` 的增量更新草案。
2. **反复纠偏规则草案（Rule Escalation Draft，仅当满足门槛时才生成）**：
   - 若会话中**不存在反复强调的纠偏**，明确标注 `规则库维持现状（零膨胀）`；
   - 若**存在反复强调的硬伤**，提炼 1 条直击根因的极简硬约束（格式严格符合 redline 规范），注明建议合并的目标文件。

### 步骤 3：生成并嵌入 Generative UI 交互卡片
在 Artifact 目录创建紧凑型 HTML 报告文件（如 `retro_card.html`），并嵌入当前对话：
```html
<agent-embed src="file:///<artifact_path>/retro_card.html"></agent-embed>
```

#### Generative UI 设计规范
- 引入官方 Tailwind 脚本：`<script src="https://www.gstatic.com/antigravity/web/dev/tailwindcss.min.js"></script>`；
- `<body class="bg-transparent text-[var(--foreground)] antialiased p-3">`；
- 全部使用宿主语义颜色变量（`bg-[var(--card)]`, `text-[var(--foreground)]`, `border-[var(--border)]`, `text-[var(--muted-foreground)]`）；
- 整体高度保持在 **280px ~ 360px** 紧凑区间，结构分为：
  - **顶部**：微徽章（`⚡ 架构测绘 & 资产同步`）、本次交付核心亮点（1~2 句话）；
  - **中部**：大地图与拓扑更新摘要（AGENTS.md 增量项）；
  - **底部**：代码块格式的标准 `git diff` 补丁预览（含地图更新或升格规则）。

### 步骤 4：询问确认与落盘执行
在卡片下方简明询问用户：
> *“是否将上述大地图更新（及规则草案）合并写入项目？回复‘写入’或‘确认’即可立即生效。”*
用户确认后，使用 `edit_file` 或 `write_file` 真正完成沉淀闭环。
  - **底部**：代码块格式的标准 `git diff` 补丁预览。

### 步骤 4：询问确认与落盘执行
在卡片下方简明询问用户：
> *“是否将上述规则草案合并写入本地 `<target_rule_file>`？回复‘写入’或‘确认’即可立即生效。”*
用户确认后，使用 `edit_file` 或 `write_file` 真正完成沉淀闭环。
