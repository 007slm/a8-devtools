# UI Polish — 界面设计感与工业美学原则 (`ui-polish`)

本技能提炼自多轮真实产品的实战打磨历程——从早期的自制散乱布局、消费级大圆角“玩具感”，经过**引入企业级秩序感（Ant Design 拐点）**、**收敛结构与领域纯洁性**，最终进化到**极简边线与跨端同源**的稳定设计语言。所有原则均抽象为纯粹的设计判断力，不绑定具体框架、字号或色号。

---

## 一、七大设计感核心原则 (Aesthetic & Structural Principles)

### 1. 企业级规整秩序：克制圆角与严谨网格（来自 Ant Design 拐点）
- **告别“玩具感”与散乱拼接**：过大的圆角、夸张的悬空阴影和随意的间距会立刻让效率工具显得幼稚松散。**工程软件应当呈现沉稳、克制、棱角清晰的微圆角节制**，通过统一的设计令牌尺度锁定所有容器与控件节奏。
- **表格式与高密度列表纪律**：数据展示拒绝被容器强行截断或出现尴尬的横向滚动条；列比例按信息权重严格分配，长路径或长文本保持单行优雅省略，点击复制、定位等高频微操作就近提供**瞬间可感知的状态反馈**。

### 2. 结构收敛：简洁主次，拒绝碎片拆分
- **避免三列碎片与多块零散白框**：复杂管理台极易滑向“左边菜单 + 中间列表 + 右边详情 + 顶部四宫格”的过度切割，导致每一块都局促不堪。
- **紧凑结构原则**：采用**可收起/展开的极简侧边导航轨 + 聚焦的主工作区**；将同纬度的顶部摘要指标收拢成少而精的一体化概览区，把宝贵的垂直视野还给核心工作内容。

### 3. 素净聚焦与领域纯洁性：不为“酷炫”硬塞噪音
- **内容区与 Hero 区去重彩**：不要为了营造“科技感”在页头硬上深色渐变巨幕、霓虹光效或装饰底纹——工具软件的主角永远是清晰的数据与任务流，视觉底座越素净通透，长期使用越耐看。
- **指标的领域纯洁性**：页面上每一块指标和图表都必须**强关联当前页面所处理的业务领域**（例如镜像管理页不塞入无关的全局网络曲线）。需要数据可视化时，交给成熟专业的图表体系做克制表达，不靠手画粗糙图形充数。

### 4. 用线条建立秩序，而非色块堆叠（Line Over Surface）
- **单一纯正底色 + 极细边线**：不要靠“灰底上叠白卡、卡上再套深浅灰块”去涂抹层级。画布、导航、卡片、编辑器保持底色高度统一，**仅依靠极克制的细边线与精准对齐建立视觉秩序**，画面立刻通透干净。
- **克制使用投影与装饰**：常规静态区块保持平实无阴影，只把极轻投影留给真正需要“浮在上方”的弹窗、菜单与瞬时提示。

### 5. 全链路氛围自洽，零视觉孤岛
- **拒绝主题撕裂**：整体已切换为明快浅色或沉稳深色时，编辑器、代码预览、规则维护框或日志面板**绝不允许局部写死对立底色**（如浅色界面中突兀出现的一整块死黑区域）。
- **空间与单行稳定性**：横向标签栏、状态胶囊与工具栏按钮必须守住水平基线，绝不因容器挤压出现意外折行或错位；外层框架锁定视口，滚动职责清晰收敛于内容区。

### 6. 信息降噪与人话表达
- **只展示用户当下要决策和编辑的对象**：内部配置、脚手架文件、元数据等工程噪音一律收起，不倾倒给界面使用者；次要关联细节采用**渐进式披露**（默认精炼摘要，按需展开）。
- **面向使用者的自然语言**：状态与动作命名遵循用户日常直觉（如「断开 / 挂载」而非晦涩的技术词汇「脱机」）。

### 7. 平台原生一致性与多入口同源
- **尊重所在操作系统的交互直觉**：去掉生硬的原生边框时，必须同步补齐顺滑拖拽与规范窗口控制；在什么系统下就遵守该系统的窗口操作习惯（不在非 macOS 平台上硬塞仿制红绿灯），顶栏品牌与工具栏保持全窗通栏基线齐平，软件内图标与桌面应用图标统一。
- **单一界面事实源**：桌面端与独立 Web 看板 / 浏览器入口必须**直接复用同一套界面表达与主题切换能力**，严禁为独立看板另外糊一套简陋替代页。

## 二、UI 审美诊断与重构流水线 (Aesthetic Review Loop)

每次新建界面或做 UI 质感提升时，按以下四步闭环执行：

1. **查结构与秩序（Structure & Discipline）**：主栏关系是否足够精炼？列表/表格是否无横向溢出且比例协调？圆角与边界线是否克制统一？是否存在违背宿主平台习惯的多余控件？
2. **做减法与除孤岛（De-clutter & Harmonize）**：删掉不必要的渐变巨幕、灰底叠色块、装饰底纹、无关领域指标及无用文件列表噪音；排查所有子区域是否存在死黑/硬编码色块孤岛。
3. **检细节与文案（Polish & Copy）**：核对横向导航/标签是否严格单行不折行、文案是否直白易懂、高频操作是否有即时微反馈、多入口视图是否彻底同源。
4. **实机观感终验（Visual Verification）**：改完必须实际启动运行并亲自审视完整画面，以最终真实呈现的耐看度与顺手度作为唯一验收标准。
